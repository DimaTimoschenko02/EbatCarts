# Features Roadmap — оружие, баффы, машинки, стата, модификаторы

Эта дока — спецификация для реализации будущими сессиями (Опус + sonnet-агенты).
Написана как тим-лидовский план для джунов: каждая фаза self-contained, с файлами,
задачами, форматами данных и ловушками. **Перед реализацией фазы: перечитать
соответствующую секцию + свериться с актуальным кодом** (файлы уходят вперёд, дока
фиксирует решения, не снапшот кода).

## Утверждённые решения (ответы Димы, 2026-07-07)

1. **Слот оружия**: один; новое НЕ подбирается, пока держишь старое (так уже работает).
2. **Charge (динамит)**: только визуальная шкала заряда в HUD. Превью траектории НЕТ (как в оригинале).
3. **Спайки**: instakill + **ускоряют носителя** (таран-оружие). Реализация ОТЛОЖЕНА — сложная сетевая синхронизация касания (см. W5).
4. **Пулемёт**: быстрые видимые снаряды (НЕ hitscan) — уклонение от очереди = часть feel оригинала. Реализация — реюз rocket-пайплайна (см. W3).
5. **Армагеддон**: очень редкий дроп. Точка призыва — решить при реализации (под собой ИЛИ на дистанции как динамит) — сделать параметром конфига `targetMode`.
6. **Баффы**: враги ВИДЯТ активный бафф (визуал на машинке). НЕ стакаются (повторный подбор = refresh таймера). Делать после основных оружий (можно перед спайками).
7. **Машинки**: выбор в лобби перед матчем. Оси: HP / скорость / размер / HP-реген (танк). Все доступны сразу, без прокачки.
8. **Стата real-time**: killfeed как в CS/Valorant (кто-кого-чем). История матчей как в Dota — потом (S3, требует персистентности).
9. **Модификаторы**: меню при создании комнаты (доступные оружия, режимы) → MatchConfig закладывается в архитектуру СЕЙЧАС (см. W0.4).

## W0. Weapon Framework (фундамент)

### W0.1 Конфиг оружия — discriminated union по категории поведения

`src/weapons/stats.ts`: сейчас `ProjectileStats` + `WEAPON_TYPES` (одна ракета).
Расширить до discriminated union — категория задаёт СЕРВЕРНУЮ симуляцию:

```ts
type WeaponStats =
  | ProjectileStats   // behavior: "projectile" — прямая (наклонная) линия: rocket, пули пулемёта
  | BallisticStats    // behavior: "ballistic"  — парабола с гравитацией: dynamite
  | DeployableStats   // behavior: "deployable" — кладётся на землю, живёт, триггерится: mine
  | AirstrikeStats    // behavior: "airstrike"  — телеграф + задержка + N взрывов: armageddon
  | AuraStats;        // behavior: "aura"       — эффект на носителе: spikes (W5, отложено)
```

Общие поля всех категорий: `id`, `displayName`, `behavior`, `baseDamage`, `aoeRadius`,
`selfDamage`, `lootWeight` (см. W0.2), `hudIcon`. Существующие поля rocket не переименовывать
(тесты и rocketSim на них завязаны) — только добавить `behavior: "projectile"` и `lootWeight`.

Спец-поля по категориям (конкретные значения — стартовые, тюнить по feel):
- **ballistic**: `gravity` (м/с²), `minLaunchSpeed`/`maxLaunchSpeed` (charge лерпит между ними), `launchPitchDeg` (~40), `maxChargeS` (~1.2), `fuseS` (взрыв по таймеру, если не коснулся земли раньше).
- **deployable**: `armDelayS` (~0.8 — не взрывается под собственной машинкой сразу), `triggerRadius` (~1.2м), `ttlS` (~30), `maxActivePerPlayer` (3 — при установке 4-й самая старая взрывается тихо/исчезает).
- **projectile** (пулемёт поверх базы): `burstCount` (патроны, ~20), `fireRateHz` (~8), `spreadDeg` малый.
- **airstrike**: `strikeCount` (5), `telegraphS` (~1.8), `scatterRadius` (~4м), `targetMode: "self" | "forward"` (решение Димы при реализации), `forwardDistM`.

### W0.2 Лут-таблица боксов

Сейчас бокс всегда даёт rocket (`MatchRoom.tickBoxes`). Ввести weighted-таблицу:
`src/weapons/loot.ts` → `rollWeapon(rng): string` по `lootWeight` из WEAPON_TYPES
(армагеддон — вес ~2 против ~30 у ракеты). Чистая функция + unit-тест на распределение.
Сервер зовёт её в pickup; уважает `MatchConfig.enabledWeapons` (W0.4).

### W0.3 Event log (сырьё для ВСЕЙ статы — закладывается с первого оружия!)

`server/rooms/MatchRoom.ts`: поле `private eventLog: MatchEvent[]`.

```ts
interface MatchEvent {
  t: number;            // ms от старта матча
  type: "fire" | "damage" | "kill" | "pickup" | "spawn" | "buff";
  actor: string;        // sessionId инициатора
  target?: string;      // жертва (damage/kill)
  weaponId?: string;    // чем
  amount?: number;      // сколько демеджа
  x?: number; z?: number;
}
```

Писать во ВСЕХ местах, где уже происходят эти события (handleFire, explodeRocket/apply damage,
killPlayer, tickBoxes pickup, respawn). Ассисты потом derive: damage по жертве в окне 5с до
kill от НЕ-киллера = ассист. Пока лог живёт в памяти комнаты и умирает с ней — S2/S3 решат
куда сливать. **Правило для всех новых оружий: любое событие демеджа обязано попадать в лог
с weaponId — иначе ретрофит.**

### W0.4 MatchConfig (заготовка под модификаторы)

При создании комнаты (lobby → create options) сервер принимает и хранит в state:

```ts
interface MatchConfig {
  enabledWeapons?: string[];  // default: все
  modifiers?: { oneHp?: boolean; microKarts?: boolean }; // G1, пока игнорируются
}
```

UI меню создания — НЕ сейчас (G1). Сейчас только протокол + хранение + учёт
`enabledWeapons` в лут-таблице. Это дешёвая закладка, которая делает G1 почти бесплатным.

### W0.5 Серверный диспетчер + generic протокол

`MatchRoom.handleFire`: вместо `player.weapon !== "rocket"` — lookup категории по
WEAPON_TYPES и диспатч в симуляцию категории (`server/weapons/<behavior>Sim.ts`).
Broadcast: обобщить `rocket:spawn` → `weapon:spawn { weaponId, kind, pos, dir, ...payload }`
(старое сообщение оставить алиасом до конца W3, чтобы не ломать клиент в пол-шага).
Клиент: `src/combat/weapons/` — рендерер на категорию (реюз существующего rockets.ts
как projectile-рендерер).

**Ворота W0**: tsc x2 + vitest; лут-таблица и event log покрыты unit-тестами;
существующая ракета работает как раньше (regression: смоук-бой два клиента).

## M1. Вторая машинка

Файл `src/kart/stats.ts` УЖЕ готов под это (KART_TYPES + buildKartPhysicsParams,
overrides поверх DEFAULT_KART_PHYSICS_PARAMS). Задачи:

1. **Каталог**: entry `mini` — `maxHp: 70`, physics overrides (`accelForce`↑, `maxSpeed`↑
   умеренно, масса↓), `modelLength: ~1.7`, модель подобрать из space-kit
   (есть разные craft_*; проверить визуально через scenes/asset_diag или каталог).
   Опционально поле `hpRegenPerS` (0 у базовой) — под будущего танка сразу заложить в интерфейс.
2. **Лобби**: экран выбора машинки перед join (src/lobby/) — карточки из KART_TYPES
   (displayName + модель/превью + hp/speed бары). Выбор → в join options.
3. **Протокол**: `kartType` в join options; сервер валидирует по KART_TYPES (fallback
   `racer`), хранит в Player schema, `maxHp` берёт из каталога. Snapshot/схема уже
   разносит Player — добавить поле.
4. **Рендер чужих**: remoteKarts.ts грузит модель по kartType игрока.
5. **Ловушки**: (а) `kartCollision.ts` — радиус: проверить, захардкожен ли; если да —
   вынести в KartStats (`collisionRadius`); (б) камера: дистанция 8м/высота 5 подобраны
   под racer — для mini скорее ок, но проверить глазами; (в) баланс mini «строго лучше» —
   первый плейтест с Димой решает, ручки в каталоге.

**Ворота M1**: два клиента с разными машинками видят правильные модели друг друга;
у mini меньше hp (килл быстрее); тесты на merge overrides уже есть — добавить на новый entry.

## W1. Мина (deployable — первое оружие через framework)

Механика: пробел → мина ставится ПОД машинкой (текущая позиция, y с heightfield).
`armDelayS` 0.8с (неактивна, полупрозрачна), затем активна `ttlS` 30с. Сервер каждый тик
проверяет: живой игрок в `triggerRadius` → взрыв = **реюз `computeAoeDamage`** из
rocketSim (вынести в `server/weapons/aoe.ts`, чтобы не тянуть minu в rocketSim).
`selfDamage: true` для мины (наступил на свою — сам виноват; проверить как в оригинале
при плейтесте, ручка есть).

Реализация:
- `server/weapons/deployableSim.ts` — чистые функции: `armMines(dt)`, `findTriggeredMine(players, mines)`, лимит maxActivePerPlayer. Unit-тесты: arm-задержка, триггер радиус, лимит.
- MatchRoom: коллекция `mines` в state (schema) — клиенты рендерят из state, НЕ из broadcast
  (мина персистентна — state-sync надёжнее event-sync при late-join/реконнекте!).
- Клиент: рендер мины (маленький тёмный цилиндр/модель из kit), полупрозрачность до arm,
  исчезновение + взрыв-VFX (реюз ракетного).
- Event log: `fire` (установка), `damage`/`kill` с weaponId "mine".

**Ловушка**: мина на рампе/склоне — y брать из heightfield, triggerRadius проверять в XZ
(вертикаль игнорировать, пока карта без мостов).

**Ворота W1**: поставил мину → отъехал → враг наехал → взрыв, урон, killfeed-событие в логе.
Смоук с двумя клиентами. Плейтест Димы.

## W2. Динамит (ballistic + charge)

Механика: удержание пробела копит charge [0..1] за `maxChargeS` (шкала в HUD у прицела,
БЕЗ превью траектории). Отпустил → бросок: `launchSpeed = lerp(min, max, charge)`,
угол `launchPitchDeg` вверх от горизонта (+ наклон земли как у ракет —
`computeLaunchPitchRad` реюз). Полёт: парабола `vel.y -= gravity*dt`. Взрыв: касание
земли (`isBlockedByTerrain` по текущему y — уже 3D) ИЛИ `fuseS` таймер. Урон — общий AOE.

Реализация:
- Input: `src/core/input.ts` — время удержания fire-кнопки; отпускание шлёт `fire { charge }`.
  Сервер клампит charge в [0..1] (не доверять клиенту). ВАЖНО: для не-charge оружий
  поведение прежнее (выстрел по нажатию) — ветвление по категории оружия В РУКАХ.
- `server/weapons/ballisticSim.ts`: `stepBallistic(pos, vel, gravity, dt)` — чистая,
  unit-тесты на параболу (максимальная дальность при полном charge на плоскости — задать
  целевое число, например 18м, и подогнать minLaunch/maxLaunch под него).
- Клиент: рендер динамита (вращающаяся палка/бокс), HUD шкала заряда.
- `weapon:spawn` несёт полную начальную vel (3D) — клиент интегрирует ту же параболу
  локально (детерминированная, без ретрансляции позиций).

**Ловушки**: (а) бросок в стену впритык — взрыв немедленный, selfDamage=false спасает,
но проверить; (б) rAF-троттлинг фоновой вкладки — параболу и на клиенте вести в sim-time,
как всё остальное; (в) charge-выстрел при смерти в момент удержания — сервер отклоняет
fire от мёртвого (guard уже есть — покрыть тестом для charge-пути).

**Ворота W2**: короткий tap = ближний навес, полный charge = дальний; дуга визуально
совпадает у стрелка и наблюдателя; шкала заряда живёт.

## W3. Пулемёт (projectile burst)

НЕ hitscan (решение Димы: видимые пули, от которых уклоняются). Пуля = маленькая быстрая
ракета без AOE: реюз ВСЕГО projectile-пайплайна (stepRocket, isBlockedByTerrain,
findProximityHit; aoeRadius=0 → прямой урон `baseDamage` только жертве proximity-hit).

Механика: подобрал пулемёт → `burstCount` 20 патронов. Удержание пробела → очередь
`fireRateHz` 8 выстр/с (сервер тикает сам от флага «держит», НЕ 8 сообщений/с от клиента:
клиент шлёт `fire:start`/`fire:stop`, сервер генерит выстрелы — меньше трафика и не
наспуфишь скорострельность). Патроны кончились → слот освобождается.

- `baseDamage` ~5 (микро), `speed` ~55, `spreadDeg` ~3 (рандом в конусе), `hitRadius` ~0.7.
- Сеть: 8 «spawn»/с × 8 игроков броадкаст — ок; если станет жирно, батчить по 2-3 пули
  в одно сообщение (отметка на будущее, не делать заранее).
- Event log: fire на каждую пулю НЕ писать (спам) — писать один `fire` на очередь
  и `damage` на попадания; accuracy пулемёта = попадания/burstCount.

**Ловушка**: смерть носителя посреди очереди → `fire:stop` серверно принудительно
(guard в killPlayer).

**Ворота W3**: очередь стреляется удержанием, патроны тратятся, слот освобождается,
урон капает по 5, уклонение реально работает (пули видно, скорость позволяет).

## W4. Армагеддон (airstrike)

Механика: активация → точка цели (`targetMode`: под собой / N метров по носу — решить
с Димой при реализации, оба режима в конфиге). На земле — 5 телеграф-колец (декали) с
рандомным разбросом `scatterRadius` вокруг точки. Через `telegraphS` — 5 взрывов
(визуал: ракеты падают с неба; физика: просто AOE в точках колец по таймеру).

- `server/weapons/airstrikeSim.ts`: `planStrikes(center, rng)` → точки; `dueStrikes(t)` →
  взрывы. Чистые, тестируемые.
- Каждый взрыв = общий AOE (`baseDamage` ~60, `aoeRadius` ~3.5, `selfDamage: true` —
  вызвал на себя и стоишь в кольце? сам дурак; проверить feel).
- Клиент: кольца-телеграфы (расширяющийся круг на земле, читаемый за telegraphS),
  падающая ракета = масштабный projectile-рендер сверху вниз (чистый визуал), взрыв-VFX.
- `lootWeight` минимальный (~2 против 30 ракеты) — «очень редкое» (Дима).

**Ловушка**: точка под собой + свои же кольца = самоубийственно на низком hp — это фича
(риск/награда), но telegraphS должен давать шанс уехать САМОМУ тоже.

**Ворота W4**: телеграф читается, задержка ощущается честной, 5 взрывов, редкость дропа.

## B1. Баффы (после основных оружий — решение Димы)

Отдельный ТИП бокса на карте (визуально отличим от оружейного — цвет/форма).
Порядок реализации по цене: **хилка → демедж-бафф → ускорение**.

- **Хилка**: мгновенно +40 hp (кламп maxHp). Чисто серверная, тривиальная.
- **Демедж ×1.5, 10с**: серверный множитель в применении урона (одна точка — apply damage
  путь). НЕ стакается: повторный подбор = refresh таймера (решение Димы).
- **Ускорение ×1.3, 5с**: клиентская физика (client-authoritative движение) — сервер
  broadcast'ит статус, клиент носителя применяет множитель к accelForce/maxSpeed
  (через physics params override, НЕ хардкод). Для игры друзей читерский вектор принят
  осознанно (гриль, удар 5).
- **Видимость врагам** (решение Димы): поле активных баффов в Player schema →
  remoteKarts рендерит ауру/кольцо цветом баффа + иконка в killfeed при килле под баффом.
- Event log: `buff` события.
- Лут: баффы из СВОИХ боксов → отдельные точки на карте (config arena) — согласовать с
  E-фазой карты (карта ×1.5 даст место).

**Ворота B1**: бафф виден и себе (HUD таймер) и врагу (аура), не стакается, таймер честный.

## W5. Спайки (ОТЛОЖЕНЫ — сетевое решение обязательно ДО кода)

Дима подтвердил: instakill при касании + УСКОРЯЮТ носителя (таран). 5с длительность.

**Почему отложено**: касание = kill, а позиции чужих машинок на клиенте — интерполяция
с лагом ~100мс. На скорости 11 м/с это 1.1м — больше корпуса машинки: «меня убило за метр»
гарантированно, если решать касание на клиенте носителя.

**Решение (зафиксировано)**: касание решает ТОЛЬКО СЕРВЕР по серверным позициям обоих
(сервер получает позиции 30Гц от каждого клиента). Radius = сумма collisionRadius обоих + ~0.3м
допуск. Носитель видит спайки на себе сразу (локальный визуал), килл приходит от сервера.
Перед реализацией: 15-минутный плейтест в ОРИГИНАЛЕ (Дима) — записать: как быстро едет
носитель, каков реальный радиус килла, что чувствует жертва. Спека дополняется после.

## S1-S3. Статистика

- **S0 (внутри W0)**: event log — сделан фундаментом, см. W0.3.
- **S1 Killfeed**: HUD-лента справа сверху (последние 4-5): `Killer [иконка weapon] Victim`,
  затухание 4с. Сервер broadcast'ит kill-событие с weaponId (уже есть в логе). Дёшево.
- **S2 Пост-матч**: расширить финальный экран: таблица каждый-vs-каждого (киллы по парам),
  ассисты (damage в окне 5с до килла от не-киллера), общий демедж/по оружиям, accuracy
  (damage-события/fire-события), время жизни (spawn→kill интервалы). ВСЁ считается из
  event log одной pure-функцией `aggregateMatchStats(log)` + unit-тесты. Дизайн-референс
  прошлой эпохи: design/gdd/profile-system.md + memory decision_profile_system (K/D,
  damage by weapon, duels, accuracy — уже продумано, реюзать).
- **S3 История матчей** (как в Dota): требует персистентности профилей на Colyseus-стеке —
  отдельное решение (перенос profiles из Godot-эпохи master server). НЕ раньше S2.

## Сквозные правила (для каждой фазы)

1. **Ворота перед коммитом**: `npx tsc --noEmit` + `npx tsc --noEmit -p server/tsconfig.json`
   + `npx vitest run` (2 известных skip в snapshotBuffer — не трогать) из web-slice/.
2. **Серверные правки** → рестарт match server (tsx не hot-reload).
3. **Smooth-values** (.claude/rules/smooth-values.md) для всего непрерывного.
4. **Все числа — в конфиги** (WEAPON_TYPES/KART_TYPES), не в код. Тюнер-дескрипторы
   по .claude/rules/param-tuner-descriptions.md, если параметр попадает в панель.
5. **Каждое оружие**: unit-тесты чистых функций симуляции + regression на ключевую
   механику + смоук два клиента + плейтест Димы. Один плейтест = одна фаза.
6. **Event log**: каждое новое оружие пишет damage/kill с weaponId — без исключений.
7. **Feel first**: если по числам «правильно», а Диме «не то» — правим к «то».
